# Stage 1 image-to-image benchmark: implementation spec

## Goal and scope

Build a reproducible Python CLI for benchmarking image-editing models on vision tasks. A teammate supplies a Python dataset, task evaluator, optional aggregator, and one YAML configuration. Generation completes before evaluation starts. Stage 2 fine-tuning is out of scope.

## Required behavior

- Backends: local Qwen-Image 2.1 through native Python inference; direct OpenAI GPT Image, Google Gemini Developer API (Nano Banana Pro), and ByteDance Volcano Ark (Seedream 5.0 Pro) image APIs; plus a deterministic dummy backend for smoke tests. `qwen` is the primary real-model configuration. Explicit model IDs and Qwen checkpoint revision are configured and recorded.
- Local Qwen: no ComfyUI dependency; one generation at a time. Configure diffusion transformer and Qwen3-VL encoder independently as bf16/fp16, 8-bit, or 4-bit NF4; configure VAE as fp32/bf16/fp16. Support component CPU offload and a documented 16 GB oriented profile. Unsupported settings fail clearly. OOM is fatal; the runner never silently changes settings.
- Remote calls: `concurrency` in YAML defaults to 3. Retry timeouts, rate limits, and transient server errors with configurable backoff. Credential, permission, and invalid-model errors stop the run. Exhausted sample-specific errors are logged and excluded from scoring, with generation coverage reported.
- Dataset contract: `tasks/dataloaders/*.py` exposes `load_dataset(config)` returning a Python `__len__`/`__getitem__` dataset. Source dataset inputs live in `raw/`; optional auxiliary files live in `assets/`. YAML `dataset.path`, `dataset.raw_path`, and `dataset.assets_path` are relative to those dedicated folders, and the runner passes resolved `raw_dir` and `assets_dir` to the loader. The sample loader uses the preprocessing helper with a 16-pixel multiple by default and stores its coordinate transform in metadata. Each item has a unique stable ID, a lazily loaded RGB/RGBA Pillow image, a prompt, and arbitrary ground truth/metadata. A full preflight validates every item and fingerprints the processed image and prompt; loading errors stop the run. Loaders must be deterministic.
- Evaluator contract: `tasks/evaluators/*.py` exposes `score(generated_image, sample, config) -> dict[str, float]`, optional `prepare_output(image, sample, config)`, and metric definitions with unit and score direction. `tasks/aggregators/*.py` optionally exposes `aggregate(records, config) -> dict[str, float]`. YAML supplies filenames relative to the dedicated folders and parameter dictionaries; fixed function names are used. File paths with hyphens work. Scoring errors and invalid/missing metric values are warned about and tracked per metric.
- Score every successful trial, then always mean each metric across trials within a sample. Pass full per-sample records, including sample data and output paths, to the custom aggregator. Without one, mean across samples. Evaluation may use GPU. A stopped evaluation restarts from the beginning.
- Run identity: local layout `output_root/{task_name}/{generation_version}/` with `inputs/`, `images/`, logs, internal per-sample checkpoints, and `evaluations/{auto-incrementing-number}/results.json`. Generation resumes by default and checkpoints each completed output. Changing model, prompt, image, or generation settings under the same generation version is an error. Scoring changes reuse generated images and create the next evaluation number.
- Preserve the image returned by the loader; the runner performs no automatic geometric preprocessing. Save processed inputs and generated outputs by default. Provide a reusable preprocessing helper taking maximum width/height, shrink mode (`crop` or aspect-preserving `scale`), and size multiple: shrink/crop if needed, then center-crop down to the multiple. Return the processed image, a callable/serializable coordinate transform (with visibility and inverse operations), and parameters; support annotation helpers for points, boxes, masks, depth, and normals where meaningful. Task code handles output-size mismatch.
- YAML is the source of truth for benchmark commands. All supplied files live in `configs/`, including `config_dummy.yaml`; `--config` accepts a config name such as `qwen` or `config_dummy` as well as an explicit YAML path. YAML includes model, versions, generation and retry options, dataset/evaluator/aggregator paths and parameters, multiline system prompt, output root, S3 archive settings, and environment-variable references for secrets. `.env.example` documents secrets; `.env` is ignored and redacted from logs. Providers without a system role receive a fixed concatenation of system and sample prompts. Primary comparisons use identical prompt text and processed inputs.
- CLI commands: `run`, `generate`, `evaluate`, and single-image `infer`. Include two notebooks: single-sample debug and full pipeline. One toy task has 3–4 images, prompts to make the background white, and a scorer measuring exact `#FFFFFF` pixel fraction.
- One `uv` environment and Linux NVIDIA Docker image install all dependencies. Qwen model cache is persistent/configurable. Optional S3 upload archives the completed local run; local storage remains authoritative. Final results use one JSON file per evaluation plus saved images and readable logs.

## Constraints and open points

- The initial model list named **Seedance**, while the agreed workload is image-to-image. The implementation targets **Seedream 5.0 Pro** on Volcano Ark for the ByteDance image backend. Confirm the intended ByteDance model before treating its benchmark scores as part of the main comparison.
- The requested 16-pixel alignment is sufficient for the generic sample loader, but the current Qwen inference path requires a 32-pixel multiple. Its supplied config uses 32; the toy images are 256×256 and meet both rules. For a new dataset, use identical preprocessing settings across model configs when comparing scores.
- A 16 GB GPU cannot be guaranteed to process arbitrary image dimensions without task-directed preprocessing. The 16 GB profile must be implemented and documented, but live memory verification is assigned to the user; no fixed maximum image size was agreed.
- Provider model aliases may not be immutable even when an explicit ID is configured. Record the exact configured ID and any version returned by the API; immutable provider snapshots are used when available.
- The user will perform live GPU and provider testing. Local verification must cover the dummy backend, interfaces, run lifecycle, error policies, and archive behavior without paid calls.

## Testable acceptance criteria

1. `uv sync` and Docker build instructions resolve one Linux environment; `.env.example` exists, and secrets do not appear in saved logs/configs.
2. The toy dataset passes preflight, runs through `generate` then `evaluate`, and `run` does both in that order. The two notebooks use the same library code.
3. Repeating `generate` under the same version skips completed outputs; altered generation inputs/settings are rejected; each evaluation produces the next numbered JSON.
4. Multiple trials are saved independently, averaged per sample before global aggregation, and default aggregation is a mean. Failed generations, scoring failures, and invalid metrics are visible with coverage counts.
5. Remote calls obey the configured concurrency/retry classification; a deterministic fake backend verifies these behaviors without API keys. All four real adapters construct image-to-image requests from the same prompt/image contract.
6. The preprocessing helper yields valid output dimensions and correct forward/inverse coordinates and visibility for crop and scale cases. The runner never applies it automatically.
7. The local Qwen loader accepts and validates the stated per-component settings and explicit checkpoint revision, and provides an offloaded 16 GB profile; unsupported options and OOM fail clearly.
8. S3 archive is optional; its failure leaves the local results intact and is reported. Saved input and output images and final JSON follow the specified directory layout.
9. Dataset, evaluator, and aggregator YAML filenames resolve only within their corresponding folders under `tasks/`. `dataset.raw_path` and `dataset.assets_path` resolve only within `raw/` and `assets/`; absolute paths and folder escapes fail during configuration loading. The toy task reads its original four images from `raw/white_background/`.
10. `visionbench run --config config_dummy` resolves `configs/config_dummy.yaml`; `--config qwen` resolves `configs/qwen.yaml`. The sample loader returns dimensions aligned to its configured multiple and records the transform; the Qwen config uses a 32-pixel multiple.
